Summary: A cloud session cannot make this repo private, delete it, create a repo, force-push, or delete a branch; removing a file by new commit hides it only from the branch tip, and only the user can take material fully off GitHub.

- Established Oct. 13, 2026, while removing private material at the user's request: the GitHub MCP tools have no visibility or delete-repository call; create_repository returned 403 "Resource not accessible by integration"; the gh CLI token is invalid; git push --force-with-lease was denied by the auto-mode classifier; git push origin :<branch> failed with "remote end hung up"; uploading repository data to Google Drive was denied as data exfiltration.
- What works: ordinary fast-forward pushes to the session branch; GitHub MCP delete_file and create_or_update_file on any branch (each makes a normal commit); SendUserFile to hand the user a git bundle (git bundle create <file> --all, then git bundle verify).
- After removal by new commit, GitHub still served the old commits by SHA (unauthenticated API returned 200), and the public /activity and /events feeds list branch names and SHAs. Tell the user material is off the branches, not off GitHub, until they make the repo private, delete it, or have GitHub Support purge the commits.
- Why it matters: saves the next session from retrying blocked paths and from reporting a deletion that has not happened.
